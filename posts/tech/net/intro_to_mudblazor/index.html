Getting started with MudBlazor: Material Design components for Blazor

Nov 21, 2023.NET & C#
  • #blazor
  • #dotnet
  • #csharp

MudBlazor is an open-source (MIT-licensed) component library for Blazor based on Google’s Material Design. It gives you layout, navigation, form, data-grid, dialog and snackbar components written in C# and Razor, so you can build a Blazor UI without writing your own CSS or JavaScript components.

Blazor itself lets you write interactive web UIs in C#. Components either run in the browser on WebAssembly, or on the server with UI updates sent to the browser over a SignalR connection (Interactive Server). Since .NET 8, the Blazor Web App template lets you pick the render mode per app or per component. MudBlazor works with both, but its components need an interactive render mode; they don’t respond to clicks under static server rendering.

The steps below were checked against MudBlazor 9.13.0 in a .NET 9 Blazor Web App with global Interactive Server rendering. MudBlazor 9.x supports .NET 8 and later.

Starting from a template

Section titled “Starting from a template”

The quickest route is MudBlazor’s own project templates, which are the Microsoft Blazor Web App template with MudBlazor already wired up:

Run dotnet new mudblazor --help to see the other options (WebAssembly and Auto interactivity). If you’d rather add MudBlazor to an existing project, do it by hand as follows.

Register MudBlazor’s services in Program.cs:

Add the font and stylesheet to the <head>, and the MudBlazor script after the Blazor script at the end of <body>. In a .NET 8+ Blazor Web App these go in Components/App.razor; older Blazor Server apps used Pages/_Host.cshtml or _Layout.cshtml, and standalone WebAssembly apps use wwwroot/index.html.

@Assets[...] (new in .NET 9) adds a content hash to the URL so browsers pick up new MudBlazor files after an upgrade. It needs app.MapStaticAssets() in Program.cs, which new .NET 9 templates include. On .NET 8, or in index.html, use the plain paths _content/MudBlazor/MudBlazor.min.css and _content/MudBlazor/MudBlazor.min.js. The template’s Bootstrap stylesheet isn’t needed alongside MudBlazor and can be removed.

Finally, add the providers to MainLayout.razor. MudThemeProvider and MudPopoverProvider are required (menus, selects and tooltips render through the popover provider); MudDialogProvider and MudSnackbarProvider are only needed if you use dialogs or snackbars.

The providers must render in the same interactive mode as the components that use them. With global interactivity (a render mode on <Routes /> in App.razor), MainLayout.razor is the right place. With per-page interactivity the layout renders statically, so the providers have to go on each interactive page instead. A “Missing <MudPopoverProvider />” error or components that ignore clicks usually means this is set up wrong.

MudLayout, MudAppBar, MudDrawer and MudMainContent work together: the main content is offset so it isn’t hidden under the app bar or the open drawer. Theming

Section titled “Theming”

MudThemeProvider takes a Theme parameter. Create a MudTheme, set its palette and typography, and pass it in to change colours across every component; it also has an IsDarkMode parameter for a dark palette. The customization docs linked below list the full set of options.
