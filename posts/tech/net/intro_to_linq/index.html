LINQ in C#: filtering, sorting, grouping and joining collections

Sep 13, 2023.NET & C#
  • #linq
  • #.net
  • #csharp

LINQ (Language Integrated Query) lets you filter, sort, project, group and join data in C# with ordinary language constructs instead of hand-written loops. It shipped with C# 3.0 and .NET Framework 3.5, and today it is part of every .NET version. The same operators work on in-memory collections (IEnumerable<T>) and, through providers such as Entity Framework Core, on databases (IQueryable<T>).

All the in-memory examples below use this data. They run as-is in a .NET console app with top-level statements (System.Linq is an implicit using in modern SDK projects):

Query syntax and method syntax

Section titled “Query syntax and method syntax”

LINQ has two forms. Query syntax looks a bit like SQL:

from names the source and a range variable, where filters, orderby sorts, and select projects each element into a new shape (here an anonymous type).

Use whichever reads better. Method syntax is more common in practice and is the only way to call operators that have no query keyword, such as Take, Skip, Distinct, Any or Count. Note that a secondary sort is ThenBy, not a second OrderBy; a second OrderBy would replace the first ordering.

Deferred execution

Section titled “Deferred execution”

Most LINQ operators don’t run when you write the query. They build a pipeline that runs each time you enumerate it (with foreach, ToList(), ToArray(), Count(), First(), and so on):

Querying a database with EF Core

Section titled “Querying a database with EF Core”

The original version of this post used LINQ to SQL (DataContext). LINQ to SQL is a legacy .NET Framework technology and isn’t available in .NET Core or .NET 5+. Use Entity Framework Core instead. Its DbSet<T> implements IQueryable<T>, so the provider translates your LINQ expression into SQL rather than running it in memory.

The query runs when it is enumerated, the same deferred execution rule as in memory. Dispose the context (the using declaration above) so its database connection is released.

Gotchas

Section titled “Gotchas”
  • Multiple enumeration. Every foreach over an unmaterialised query re-runs it. Against a database that means another round trip; call ToList() once if you need the results twice.
  • IEnumerable vs IQueryable. Once a database query becomes IEnumerable<T> (for example after AsEnumerable() or ToList()), the remaining operators run in memory on every row fetched. Keep filters before that point.
  • Not every C# expression translates to SQL. EF Core throws if it can’t translate a method call in a Where, rather than silently pulling the whole table.
  • First vs FirstOrDefault. First throws on an empty sequence; FirstOrDefault returns default (null for reference types).
