Dart functions on Appwrite: base64 encode, HTTPS check and email slicer

Nov 29, 2024Mobile & Android
  • #dart
  • #appwrite

Caution

The functions in the dart_fns repo use Appwrite’s old start(req, res) entrypoint with req.payload and req.variables. Appwrite 1.4 replaced it with a single context argument (context.req, context.res, context.log). The examples below use the current syntax.

Appwrite is an open-source backend-as-a-service: auth, databases, storage and serverless functions, either self-hosted or on Appwrite Cloud. Its Functions product runs your code in a managed runtime and gives each function an HTTP endpoint, so you don’t have to run a server for small utilities like the ones below.

The functions

Section titled “The functions”

These are plain Dart and run anywhere. Each one became its own Appwrite function in the repo.

Base64 encode

Section titled “Base64 encode”

utf8.encode turns the string into bytes and base64Encode turns those bytes into a base64 string. Both live in dart:convert.

Check for an HTTPS URL

Section titled “Check for an HTTPS URL”

Uri.tryParse returns null instead of throwing on malformed input. Checking host matters because https: on its own parses fine but isn’t a usable URL. This only checks the format; it doesn’t check that the host exists or that its certificate is valid.

Email slicer

Section titled “Email slicer”

This splits on @ and rejects anything without exactly one. It isn’t a full email validator: quoted local parts such as "a@b"@example.com are valid addresses that this rejects.

Running one as an Appwrite function

Section titled “Running one as an Appwrite function”

An Appwrite Dart function is a package whose entrypoint (lib/main.dart in the starter template) exports main(context). The handler reads the request from context.req and must return one of the context.res helpers (text, json, binary, redirect, empty). Here is the encoder:

context.req also has bodyJson, headers, query, path and method. Use context.log and context.error instead of print; their output shows up in the execution logs in the Appwrite Console. res.send still exists but is deprecated in favour of res.text.

These functions don’t call any Appwrite APIs, so they don’t need the SDK. If yours does, add dart_appwrite (dart pub add dart_appwrite) and build the client from the values the runtime provides:

The x-appwrite-key header carries a short-lived API key that Appwrite issues for the execution, scoped to the permissions you grant the function, so you don’t need to paste a long-lived key into your code or variables.

Deploying

Section titled “Deploying”

With the Appwrite CLI:

Without the CLI, package the function folder with tar --exclude code.tar.gz -czf code.tar.gz ., then upload it in the Console under the function’s Create deployment > Manual tab and set the entrypoint (lib/main.dart).

Once deployed, you can run the function from the Console’s Execute button or call its domain with an HTTP request; the request body becomes context.req.bodyText.
