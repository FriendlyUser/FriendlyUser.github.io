Async JavaScript: promises, async/await and fetch

Feb 17, 2023JavaScript & web
  • #js
  • #introToJs
  • #express
  • #javascript

The only way to learn a new programming language is by writing programs in it. — Brian Kernighan and Dennis Ritchie, The C Programming Language

JavaScript runs your code on a single thread, so slow work like network requests, timers and file I/O is done asynchronously: you start the operation, the rest of your code keeps running, and you handle the result when it arrives. JavaScript gives you three ways to handle that result: callbacks, promises, and async/await (which is built on promises).

Promises

Section titled “Promises”

A promise is an object representing the eventual result of an asynchronous operation. It is always in one of three states:

  • pending: the operation hasn’t finished yet
  • fulfilled: it finished and a value is available
  • rejected: it failed and an error (the rejection reason) is available

Why use promises

Section titled “Why use promises”

With plain callbacks, every step that depends on the previous one gets nested inside it, and error handling has to be repeated at each level (“callback hell”). Promises let you chain steps with .then() and handle errors once with .catch().

The function passed to new Promise receives resolve and reject. Calling resolve(value) fulfils the promise and runs the .then() callback; calling reject(error) rejects it and runs the .catch() callback. Reject with an Error object rather than a string so you keep a stack trace.

async/await

Section titled “async/await”

async/await (ES2017) is syntax over promises that lets you write the same logic top to bottom. An async function always returns a promise, and await pauses that function until the promise settles. Rejections become exceptions you handle with try/catch:

To run independent operations at the same time instead of one after another, start them all and await Promise.all([...]) (fails as soon as one rejects) or Promise.allSettled([...]) (waits for all and reports each outcome).

HTTP requests

Section titled “HTTP requests”

The most common use of async code in the browser is talking to a server over HTTP. The request methods you’ll use most:

  • GET: read a resource
  • POST: send data to be processed, often to create a resource
  • PUT: replace a resource
  • PATCH: partially update a resource
  • DELETE: delete a resource

An endpoint is the URL you send a request to, such as https://example.com/books?title=harry+potter, where https://example.com/books is the path and title=harry+potter is a query string parameter.

XMLHttpRequest vs fetch

Section titled “XMLHttpRequest vs fetch”

Browsers have two built-in APIs for making requests. The older one is XMLHttpRequest (XHR), which is event/callback based:

The newer fetch() API returns a promise and is what you should reach for today. It is also available in Node.js 18 and later without any imports.

“AJAX” isn’t a separate API; it’s the general technique of requesting data from the page without a full reload, and both XHR and fetch can do it. Practical differences between the two:

  • fetch returns promises, so it works with async/await; XHR uses event handlers.
  • fetch exposes the response body as a stream (response.body), so you can process large responses as they arrive.
  • XHR has upload.onprogress for upload progress events; fetch has no equivalent.

Cancelling a request with AbortController

Section titled “Cancelling a request with AbortController”

AbortController lets you cancel a request in flight, for example when the user starts a new search that replaces the old one. Pass its signal to fetch; calling abort() rejects the promise with an AbortError:

For a timeout, you don’t need your own controller: fetch(url, { signal: AbortSignal.timeout(5000) }) aborts after five seconds (the rejection is then a TimeoutError).

Scraping HTML with fetch and Cheerio

Section titled “Scraping HTML with fetch and Cheerio”

fetch gets you the raw HTML of a page but doesn’t parse it. For server-side scraping in Node.js, Cheerio parses HTML and gives you a jQuery-like API for selecting elements (npm install cheerio). Save this as scrape.mjs so Node treats it as an ES module, which allows import and top-level await:

Cheerio doesn’t run JavaScript, so it only sees what’s in the HTML the server sends. For pages that build their content client-side, use a headless browser such as Puppeteer or Playwright instead.

Caching responses

Section titled “Caching responses”

If your app requests the same data repeatedly, you can keep responses in memory and skip the network on repeat requests. Cache the promise rather than the resolved data: then two calls made at the same time share one request, and the function always returns a promise.

This cache never expires and grows without limit, which is fine for a small, fixed set of URLs. For anything bigger, reach for a library:

  • quick-lru and tiny-lru: in-memory LRU caches that evict the least recently used entries once a maximum size is reached.
  • memoizee: memoizes function results, including promise-returning functions, with optional expiry.
  • lscache: stores values in localStorage with an expiry time, so they survive page reloads.

Also remember that the browser already has an HTTP cache. If the server sends sensible Cache-Control headers, repeat fetch calls may be served without a network round trip at all.
